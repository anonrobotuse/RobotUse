Abstract

Code-based robot policies expose detailed execution logic, while coarse skills can limit adaptation and recovery. RobotUse lets agents specify targets, candidate poses, and bounded adjustments; existing perception, geometry, planning, and control modules handle execution. Local agents retain subgoal observations and revisions, returning outcomes and unresolved constraints to the main agent. An outer loop reviews the main trajectory and updates a versioned playbook while keeping the backend fixed. Across 40 RoboLab tasks and three runs, RobotUse achieves 45.00% success, compared with 38.33% for CaP-X and 20.00% for GaP (ORS). Removing grasp tools causes a smaller success reduction for RobotUse. Harness revisions raise success from 19/40 to 22/40 on the evaluated task catalog. These results support outcome specification as a boundary between model reasoning and backend execution.
